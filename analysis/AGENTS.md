# Agent 요약: Analysis

## 1. 책임 (Responsibility)
이 에이전트는 원시 사용자 상호작용 로그를 구조화되고 실행 가능한 가이드로 변환하는 배치 처리 모듈입니다. 데이터베이스에서 데이터를 읽고, 경로 찾기 분석을 실행하여 공통적인 성공 사용자 여정을 식별하며, 결과 가이드를 서버에서 사용할 수 있도록 데이터베이스에 다시 기록합니다.

## 2. 입력 / 출력 (Inputs / Outputs)
### 입력
- **데이터베이스 (`followme_db.event_logs`)**: 원시 사용자 상호작용 로그 컬렉션을 읽습니다.
- **`TARGET_GOAL_URL` (하드코딩됨)**: `main_analyzer.py`에 미리 정의된 URL로, 사용자 경로의 "성공" 조건을 결정합니다.
- **환경 변수**: 데이터베이스 연결을 위한 `MONGO_URI` (서버의 `.env` 파일에서 읽어옴).

### 출력
- **데이터베이스 (`followme_db.analyzed_guides`)**: 대상 URL과 CSS 선택자를 포함한 단계 시퀀스를 포함하여 생성된 가이드 데이터를 기록합니다.
- **표준 출력**: 실행 중 콘솔에 상태 메시지 및 분석 결과를 출력합니다.

## 3. 내부 구조 (Internal Structure)
- **`main_analyzer.py`**: 분석 파이프라인을 처음부터 끝까지 실행하는 오케스트레이터 스크립트입니다.
- **`data_loader.py`**: MongoDB에 연결하고 원시 `event_logs`를 pandas DataFrame으로 로드합니다.
- **`preprocess.py`**: 이벤트를 정렬하고, 세션별로 그룹화하며, 노이즈를 필터링하여 원시 데이터를 정리합니다.
- **`path_finder.py`**: 핵심 분석 로직을 포함합니다. 성공적인 세션(목표 URL에 도달한 세션)을 필터링하고 빈도 분석을 사용하여 가장 일반적인 사용자 행동 시퀀스를 찾습니다.
- **`generate_guide.py`**: 식별된 경로 시퀀스를 공식 가이드 스키마로 변환하고 `analyzed_guides` 컬렉션에 저장합니다.
- **실행 흐름 (파이프라인)**:
  1. `main_analyzer.py`가 실행됩니다.
  2. `data_loader`가 MongoDB에서 데이터를 가져옵니다.
  3. `preprocess`가 DataFrame을 정리합니다.
  4. `path_finder`가 가장 일반적인 클릭 시퀀스를 발견합니다.
  5. `generate_guide`가 시퀀스를 가이드로 포맷하고 저장합니다.

## 4. 의존성 (Dependencies)
### 내부 모듈
- 스크립트들은 파이프라인으로 구성되어 있으며, `main_analyzer.py`는 디렉토리의 다른 모든 모듈에 의존합니다.

### 외부 모듈
- `pandas`, `numpy`, `scikit-learn`: 데이터 조작 및 분석에 사용됩니다.
- `pymongo`: 모든 데이터베이스 상호작용에 사용됩니다.
- `python-dotenv`: `.env` 파일에서 `MONGO_URI`를 로드하는 데 사용됩니다.
- **파일 시스템**: `.env` 파일에 접근하기 위해 `server` 디렉토리 위치에 강하게 결합되어 있습니다 (`../server/.env`).

## 5. 검사 결과 (Inspection Findings)
- **기능적 결함**: `path_finder`의 요소 선택자 식별 방법(`tagName(id=..., class=...)`)은 작동하지 않는 플레이스홀더입니다. 확장 프로그램이 사용할 수 있는 유효한 CSS 선택자를 생성하지 않습니다.
- **설계 결함**:
  - `server`의 `.env` 파일에 대한 의존성은 모듈 독립성을 깨는 심각한 결합 문제입니다.
  - 분석 로직은 전체 경로의 단순한 빈도 수 계산으로, 견고하지 않습니다. 공통 하위 경로 또는 변형을 식별할 수 없습니다.
- **유지보수 리스크**: `TARGET_GOAL_URL`이 하드코딩되어 있어 다른 사용자 목표를 분석하려면 코드 변경이 필요합니다. 이는 구성 가능한 매개변수여야 합니다.
- **프로토타입 흔적**: 전체 경로 찾기 알고리즘은 플레이스홀더이며 주요 기술 부채를 나타냅니다. 분석이 프로덕션 시스템에 충분히 정교하지 않습니다.
- **추천 리팩터링**:
  - 이 모듈에 `MONGO_URI`를 명시적 환경 변수로 만들어 `server`의 `.env` 파일과의 결합을 해제합니다.
  - 경로 찾기 로직을 더 고급 시퀀스 마이닝 알고리즘(예: GSP 또는 PrefixSpan)으로 교체합니다.
  - 플레이스홀더 문자열 대신 요소에 대한 고유하고 안정적인 CSS 선택자를 생성하는 견고한 함수를 구현합니다.
  - `goal_url`을 `main_analyzer.py`의 명령줄 인수로 만듭니다.

## 6. 테스트 용이성 (Testability)
- **단위 테스트**: 파이프라인의 각 단계(`preprocess`, `find_common_paths` 등)는 샘플 pandas DataFrame을 입력으로 전달하고 출력을 검증하여 개별적으로 테스트할 수 있습니다.
- **통합 테스트**: 전체 파이프라인은 테스트 데이터베이스를 설정하고, 샘플 로그로 채운 다음, `main_analyzer.py`를 실행하고, `analyzed_guides` 컬렉션의 내용을 확인하여 테스트할 수 있습니다.
